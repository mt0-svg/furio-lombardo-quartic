A new version of the paper of v1.1.0, written to be read as mathematics: its body names no file, script or listing and carries no Lean code, and each formalized proof ends with one sentence naming its main Lean declaration. Lemmas 2.2 and 3.2 are written out, and long proofs are split into paragraphs. The proofs that are finite checks on explicit data are in an appendix, the introduction lists the steps of the proof, and Section 9 says what is checked and by which tools; how the continuous integration runs the checks is in the README. The paper and the repository keep only what the proof uses: the remark on the route through the Mordell-Weil group of the Jacobian, the search of the introduction, the earlier computations and the second implementations are removed, with their scripts and outputs. The bibliography cites the formalization as this companion repository. A new file, `STATEMENTS.md` ("From the paper to the proof", written by `paper/statement_map.sh` from the paper), gives for each numbered statement its Lean declarations and for each section that reports a computation its scripts and recorded outputs; the README links to it and is a few screens long.

- Lean: the proof is that of v1.1.0. The docstring of the declaration that proves each numbered statement gives the statement's number in the paper.
- Checks on GitHub: Comparator checks `FurioLombardo.conjecture_1_6` against `FurioLombardo/Challenge.lean`, and nanoda, an implementation of the Lean kernel written separately, checks again every declaration the theorem depends on; the Lean kernel, which checked them during the build, is not run a second time (`config.json`, with `.github/comparator-lean-kernel.patch` applied to Comparator). The computation jobs and the Computation Certificates badge are removed: every computation of the proof is checked by the Lean kernel. The README badges (Lean Proved, Lean Comparator) are written by the latest run started by hand on the default branch and link to that run.
- Code: `code/` keeps the programs that wrote the Lean data, the files they read, the files that the comments of the Lean sources cite (among them `code/second-implementations/class-number/zimmert_bounds.gp`) and the script that prints the numbers of the proof of Proposition 2.1 (`code/field/zimmert_num_check.gp`), with their recorded outputs, and the records of the checks of the formal proof; the three PARI/GP libraries these programs read are now in `code/lib`, and `code/README.md` maps each Lean data file to its program.
- Recorded outputs: `code/formal-proof/clean_build_summary.sh` summarizes the three runs of the recorded clean build (`clean_build_summary.out`). The record of the Comparator times is the logs of two jobs of GitHub Actions in the repository `mt0-svg/nanoda-trials`, shipped as `comparator_trial_kernel.log.gz` and `comparator_trial_nanoda4.log.gz` and read by `comparator_time.sh` into `comparator_time.out`; they show that both jobs checked out tag v1.1.0 (commit d3f8953). The run number, 36763054119, is given as provenance only: the logs do not hold it. `comment_only_build_sources.sh` shows that the Lean code of v1.1.0, on which the clean build ran too, is the code of this version up to comments (`comment_only_build_sources.out`). The scripts of `code/field` now write their Lean files under `FurioLombardo/M2` at the root of the repository.

Assets: the paper, `verification-v1.2.0.tar.gz` (the complete output of every check of the CI run), and `furio-lombardo-quartic-x86_64-unknown-linux-gnu.tar.gz`, the Lake build that Comparator checked, which `lake build :release` and dependent packages download.
