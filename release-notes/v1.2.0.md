A new version of the paper of v1.1.0, written to be read as mathematics: its body names no file, script or listing and carries no Lean code, and each formalized proof ends with one sentence naming its main Lean declaration. Lemmas 2.2 and 3.2 are written out, long proofs are split into paragraphs, and a referee's cold read added the steps it found missing. The bibliography cites the formalization as this companion repository. A new file, `STATEMENTS.md` ("From the paper to the proof", written by `paper/statement_map.sh` from the paper), gives for each numbered statement its Lean declarations and for each section that reports a computation its scripts and recorded outputs; the README links to it and is a few screens long.

- Lean: the proof is that of v1.1.0. The docstring of the declaration that proves each numbered statement gives the statement's number in the paper.
- Checks on GitHub: Comparator checks `FurioLombardo.conjecture_1_6` against `FurioLombardo/Challenge.lean`, and nanoda, an implementation of the Lean kernel written separately, checks again every declaration the theorem depends on; the Lean kernel, which checked them during the build, is not run a second time (`config.json`, with `.github/comparator-lean-kernel.patch` applied to Comparator). A new job reruns the Sage second implementations (descent set, local group and covering, Selmer space) and compares each output with the recorded one (`code/second-implementations/rerun.sh`). The README badges (Lean Proved, Lean Comparator, Computation Certificates) are written by the latest run started by hand on the default branch and link to that run.
- Recorded outputs: `sunits_basis.out`, `lattice.out` and the four `centres_twist*_prec*.txt` of `code/second-implementations` printed the names the saved files had before they were renamed; they are written again by the current programs, and only those names change. `code/formal-proof/clean_build_summary.sh` summarizes the three runs of the recorded clean build (`clean_build_summary.out`). The record of the Comparator times is the logs of two jobs of GitHub Actions in the repository `mt0-svg/nanoda-trials`, shipped as `comparator_trial_kernel.log.gz` and `comparator_trial_nanoda4.log.gz` and read by `comparator_time.sh` into `comparator_time.out`; they show that both jobs checked out tag v1.1.0 (commit d3f8953). The run number, 36763054119, is given as provenance only: the logs do not hold it. `comment_only_build_sources.sh` shows that the Lean code of v1.1.0, on which the clean build ran too, is the code of this version up to comments (`comment_only_build_sources.out`). The scripts of `code/field` now write their Lean files under `FurioLombardo/M2` at the root of the repository, and `class_number_primes_rerun.sh` compares the blocks it generates with those of `FurioLombardo/M2/Data` there and exits with status 1 when they differ; `class_number_primes_rerun.out` is a new run of it.

Assets: the paper, `verification-v1.2.0.tar.gz` (the complete output of every check of the CI run), and `furio-lombardo-quartic-x86_64-unknown-linux-gnu.tar.gz`, the Lake build that Comparator checked, which `lake build :release` and dependent packages download.
