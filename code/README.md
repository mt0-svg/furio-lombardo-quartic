# Code

The programs that wrote the data of the Lean proof, each next to its recorded output, and the records of the checks of the formal proof. The proof does not trust these programs: the Lean kernel checks what they wrote (section "The data of the checks" of the paper). Paths are relative to the root of the repository.

- Each script says in its header where to run it and how. The scripts of a directory are run from that directory.
- In file names, `twist0` and `twist1` are the twists k = 0 and k = 1; `v`, `w12`, `w6` and `w7` are the places v, w_12, w_6 and w_7 of K; `prec<n>` is a p-adic working precision.
- The scripts that read or write Lean files find the Lean package at the root of the repository (`../../FurioLombardo/...` from a directory of `code/`). They were run with the package in a directory `lean/` of their working tree, so the recorded outputs that print these paths show `../../lean/FurioLombardo/...`.
- Some recorded outputs were written before the scripts and directories got their present names, and print the old names; `renames.tsv` maps each old path to the new one.
- `lib/` holds three PARI/GP libraries: `pball.gp` (ball arithmetic with proved error bounds over a totally ramified extension of Q_p), `richelot.gp` (descent by a Richelot isogeny) and `td2loc.gp` (local images of the 2-descent map).
- The comments of the Lean sources cite some files of this directory for a construction, a design or a value; these files are kept so that every such reference resolves, and the proof does not depend on them.

## The checks of the formal proof

`formal-proof` holds:

- the build of the Lean package from an empty build directory: `clean_build.sh`, its three runs in `clean_build.out` (the first from empty and stopped, the second and the third resumed on it with `RESUME=1`, the third ending with `result: ok`), the time of each module in `clean_build_modules.txt`, and their summary in `clean_build_summary.out`, printed by `clean_build_summary.sh`;
- the Comparator and nanoda times, read by `comparator_time.sh` into `comparator_time.out` from two job logs on GitHub hosted runners (4 CPUs, 15 GB): `comparator_trial_nanoda4.log.gz` (the export of the solution that nanoda reads, then nanoda on it, 4 threads) and `comparator_trial_kernel.log.gz` (Comparator with the Lean kernel alone);
- `comment_only_build_sources.sh` and its output: the build and the Comparator timing ran on the Lean code of tag v1.1.0, which is the code of this version up to comments;
- the axioms of the delivered theorems (`main_axioms.lean`, `main_axioms.out`), the facts that `ci.yml` prints in its badges (`facts.lean`), and a control showing that a theorem proved by `native_decide` depends on an axiom of its own (`native_decide_control.lean`, `native_decide_control.out`).

### Shipped data whose writer is not shipped

In `earlier-computations`: `local_images_twist*_e*.bin` (the local images of the Selmer computation at the places above 2), `export/centres_pari_twist*.txt` (the PARI/GP values at the centres), `richelot_data.gp` (the Richelot data of the Prym curves), `phi_known_lifts.gp` (the values of phi_k at the known lifts), `pullback_known_lifts.gp` (the tiny integrals at the known lifts), `field_l42_polynomial.gp` (the polynomial of L), `field_n84_polynomial.gp` (the polynomial of N), `field_kprime_data.gp` (a field K' of degree 42, read by `field_n84_galois.gp`) and `bruin_form_orbit21.gp` (the exact Bruin form over K, which `bruin_form_reduce.gp` reduces to `bruin_form.gp`). In `selmer-global-bound`: `sunit_generators_data.gp` (the generators that `mu_t_cert.gp`, `pgen_polynomials.gp`, `residue_characters.gp`, `sunit_data_lean.gp` and `selmer_space_new_generators.gp` read). In `local-group`: `di_values_ball_data.lean` (the input of `di_values_ball_run.sh`).

### Shell drivers

The header of each shell driver says how its recorded run was made: most ran each command under a memory-capping wrapper, `cap`, that is not part of this repository, and the commands themselves run without it. `local-group/di_values_ball_run.sh` and `selmer-global-bound/sunit_data_install.sh` take lock files under `/tmp` with `flock`. `formal-proof/clean_build.sh` reads a command prefix and a lock file from the environment (`RUN_WRAP` and `LOCK`, empty by default).
